# 群聊唤醒

AstrBot 插件：监听群聊冷场，在符合条件时主动发送唤醒消息。它只负责“什么时候开口、开口说什么”，不做任何回复判断；群友回应之后，正常聊天仍由 AstrBot 和其他回复插件接管。

## 行为语义

1. 第一次目标时间为“最后真实活动时间 + 冷场阈值 + 本轮随机延时”，在目标到达后的巡检中开始生成唤醒消息。默认冷场 40 分钟，再随机延时 0～5 分钟。
2. 成功发送一次，或标准消息链正常选择不回复，都视为完成本轮唤醒尝试。下一轮从上一次尝试时间重新计算“冷场阈值 + 新的随机延时”。
3. 本插件的主动唤醒不会刷新最后真实活动时间，也不会重启死群计时。平台在 120 秒内回显本插件刚发出的唤醒内容时，只记录回显，不视为新群聊活动。
4. 群友消息或正常聊天中的机器人回复是真实活动：它们都会从新时间重新计算冷场、随机延时和死群上限。
5. 生成或发送失败会对该群触发熔断，之后再观察到该群出现正常回复才会恢复。
6. “死群上限”始终从最后真实活动起算，超过后不再主动开口。例如最后活动在 12:00，冷场 40 分钟、死群上限 360 分钟：第一轮约 12:40～12:45；若没人回应，下一轮再从第一次尝试后计算 40+新随机；到 18:00 后停止。实际次数会受随机延时、模型耗时、每日上限和免打扰影响，可能少于 9 轮。
7. 标准消息链如果被其他插件阻止、主动保持沉默或没有可发送结果，本轮不计每日额度，但会安排下一轮；不会在同一目标时间连续排队重试。

随机延时每轮尝试只抽取一次并持久化，不会在每次巡检或重启时重新抽取；该轮成功发送或标准消息链正常无果后，会从新的尝试时间再次抽取。群友新消息或其他真实活动会取消旧计划。修改冷场阈值或随机延时上限后，下次符合条件的巡检会重算。将“随机延时上限（分钟）”设为 `0` 可恢复固定冷场阈值。

例如冷场 40 分钟、随机上限 5 分钟，第一轮抽到 2 分钟，则目标是最后活动后的第 42 分钟；这次完成后，下一轮重新抽取，不再复用这一次的 2 分钟。随机等待不会绕过免打扰、黑白名单、每日上限或死群上限。


## 提示词

在“标准消息链”中，整段内容会在 `on_llm_request` 阶段追加到真正发给模型的 `req.system_prompt`，因此正常进入主 Agent 的请求应能在 `astr_agent_prepare.system_prompt` 中看到它。框架的人格、Skills 和其他插件的注入保留不变。合成事件的用户消息只有固定触发标记“群聊唤醒”，不会再重复放入整段任务内容。

“轻量工具调用”和“纯文本生成”仍将该配置作为用户提示词，保持原来的调用方式。所有模式都只作用于本插件的后台任务，不改变日常群消息的人格或提示词。

所有占位符都是可选项，不需要可以不写：

| 占位符 | 含义 |
|---|---|
| `{{persona}}` | 当前会话人格。两个直连模式中，写了则内联，不写则单独作为系统提示词；标准消息链本身会注入人格，通常无需重复填写 |
| `{{time}}` | 当前本地时间，格式 `YYYY-MM-DD HH:MM:SS` |
| `{{group_id}}` | 平台群号或 UMO 中的会话 ID |
| `{{group_name}}` | 群名；取不到时使用群号 |
| `{{recent_history}}` | 最近 N 条群聊记录，格式为“昵称: 内容” |
| `{{recent_topics}}` | 本插件最近发过的唤醒内容，用于防止连续重复话题 |

未知占位符不会被改动，会按原文传给模型。

示例：

```text
现在有点冷场了。参考最近的群聊内容，自然地开一个小话题，只输出要发到群里的那句话。

当前时间：{{time}}
群名：{{group_name}}
最近聊天：
{{recent_history}}
```

如果要让机器人发图片、自拍等，提示词里直接写模型该使用哪个工具，例如：

```text
本次是后台主动唤醒任务，不是群友临时要求。保留人格的语言风格。
本轮请调用 aiimg_generate 工具，使用自拍人物参数 [self]，发送一张自拍，再接一句简短的话。
本次任务不因心情取消；工具失败时不要声称已经完成。
```

上面的工具名和参数仅为示例，请按实际安装的工具修改。搭配“轻量工具调用”或“标准消息链”使用；代码不会自动添加这些任务规则，也不会强制调用绘图工具。系统提示词追加在同一个角色中，不天然高于人格设定，用户需要自行写清后台任务的例外；仍不能保证模型每次都会执行工具或出图成功。

## 生成模式

| 模式 | 调用路径 | 提示词位置 | 框架集成 |
|---|---|---|---|
| 轻量工具调用（默认） | `context.tool_loop_agent()` + 合成事件 | 用户提示词 | 能执行工具，不走完整消息链；失败由本插件拦截 |
| 纯文本生成 | `context.llm_generate()` | 用户提示词 | 不执行工具，不走完整消息链；失败由本插件拦截 |
| 标准消息链 | 后台事件 → 事件队列 → 框架处理链 | 系统提示词 | 经过插件消息处理、请求/响应钩子、回复修饰和发送；使用当前会话的 Agent Runner 设置 |

两个直连模式由本插件发送最终文本；标准消息链由框架组织回复并通过受控事件发送，本插件不会再补发一遍。工具通过本次事件发送的图片、语音可正常发出，分段回复或先发图再发文只计一次唤醒。某个工具若自行绕开事件调用平台 API 或 `context.send_message()`，不在这个发送出口的拦截和计次范围内。

标准模式使用群的真实机器人 ID、平台元信息和原 UMO，但发送者是虚拟 ID `0` / `GroupWakeup`，不会冒充群友，也不授予管理员权限。本插件不把该事件算作人类活动。其他插件仍可能记录、修改、拦截这条事件，或要求原生 OneBot 事件/客户端字段，因此不能保证与所有插件完全兼容，也没有针对某个错误拦截插件做专门适配。普通消息链的历史记录规则仍会生效，可能保存触发标记和回复。

当使用 AstrBot 内置主 Agent 且处理链未被提前终止时，可获得正常的请求准备、完成统计和工具追踪；其他 Agent Runner 或第三方插件接管回复时，追踪内容跟随其实现。标准模式关闭本次请求的实时流式输出，避免错误文本以片段形式提前发送；第三方插件自行产生的流也先收齐再检查。


标准消息链的等待上限包含排队时间；超时或卸载会停止本次事件并关闭其后续发送，不会强制终止第三方插件已经创建的外部任务。依赖事件结束后再异步发送的插件可能被此保护拒绝。处理期间有新的群活动时，也会取消尚未发送的内容。
“指定模型服务商”留空时使用当前会话的聊天模型；填写后使用指定服务商。

## 配置

下表名称和排列顺序与插件配置页面一致。

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| 冷场阈值（分钟） | 40 | 无群聊活动达到此时长后，再等待本轮随机延时 |
| 随机延时上限（分钟） | 5 | 冷场后额外等待 0 到该值的随机时长，范围 0～120；`0` 表示不加延时 |
| 死群上限（分钟） | 360 | 从最后真实活动起算，超过后不再主动开口；主动唤醒不会重置计时 |
| 每日每群唤醒上限 | 1 | 每个群每天最多成功唤醒的次数；`0` 表示不限制。要允许多轮冷场唤醒，需设为 `0` 或更大的次数 |
| 后台巡检间隔（秒） | 60 | 多久检查一次各群是否满足唤醒条件 |
| 记录最近群聊内容 | 开 | 是否记录供唤醒提示词参考的最近群聊 |
| 注入提示词的最近消息条数 | 20 | 占位符 `{{recent_history}}` 最多包含的消息条数 |
| 防重复保留的最近话题条数 | 5 | 占位符 `{{recent_topics}}` 最多保留的唤醒话题条数 |
| 启用夜间免打扰 | 开 | 开启后，免打扰时段内不发起唤醒 |
| 免打扰开始时间 | 23:00 | 免打扰时段的起点 |
| 免打扰结束时间 | 07:00 | 免打扰时段的终点，支持跨午夜 |
| 唤醒内容生成模式 | 轻量工具调用 | 轻量工具调用 / 纯文本生成 / 标准消息链 |
| 指定模型服务商 | 空 | 留空跟随当前会话模型 |
| 轻量工具调用最大轮数 | 8 | 仅作用于轻量工具调用；标准消息链跟随框架设置 |
| 轻量工具调用单次工具超时（秒） | 120 | 轻量工具调用模式下，每次工具执行最多等待的时间 |
| 标准消息链等待上限（秒） | 600 | 包含排队、模型、工具及回复处理时间，范围 30～3600 |
| 黑名单（永不唤醒） | 空 | 名单中的群永不唤醒；优先于白名单 |
| 白名单（留空表示所有群） | 空 | 非空时只唤醒名单中的群，仍受黑名单及其他条件限制 |
| 唤醒提示词（整段自定义） | 默认模板 | 自行填写唤醒任务要求，支持上文列出的占位符 |

## 名单填写

黑名单和白名单都支持以下两种值：

- 平台群号：例如 aiocqhttp 的 QQ 群号
- UMO 会话 ID：例如 `aiocqhttp:GroupMessage:123456` 中的 `123456`

规则：黑名单一票否决；白名单非空时，只唤醒白名单中的群。

## 状态文件

插件状态保存在 AstrBot 分配给插件的数据目录中的 `state.json`，内容包括：

- 每个群的最后活动时间
- 群号及最近观察到的机器人 ID
- 最近一次唤醒尝试时间
- 当天已发送次数
- 最近唤醒话题
- 最近群聊记录
- 熔断状态和原因
- 每轮随机唤醒目标对应的尝试起点和配置

删除 `state.json` 可以重置所有群的状态。

## 平台限制

主动消息依赖平台适配器支持。AstrBot 的 QQ 官方接口通常不支持程序主动推送；aiocqhttp / OneBot 群聊可正常主动发送。

## 边界

- 不注册回复命令
- 请求、响应及回复修饰钩子只作用于本插件创建的后台事件
- 不拦截或改写任何用户消息
- 只监听群消息、定时巡检并按允许的轮次主动发送唤醒消息
